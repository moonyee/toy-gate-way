# 마이크로서비스 아키텍처 (MSA) 게이트웨이 서버

### API 게이트웨이 (API Gateway)

본 프로젝트는 외부 클라이언트의 모든 요청을 받아 처리하는 API 게이트웨이를 구현합니다. 게이트웨이는 시스템의 단일 진입점으로서, 백엔드 마이크로서비스로의 요청을 안전하고 효율적으로 라우팅하는 역할을 담당합니다.



### 개발 환경

* 빌드 툴: Gradle
* Spring Boot: 3.5.5
* Java: 17
* 패키징: Jar



### 주요 특징

* 단일 진입점: 모든 클라이언트 요청은 이 게이트웨이를 통해서만 백엔드 서비스에 접근할 수 있습니다.
* 중앙 집중형 보안: JWT 기반 인증/인가를 게이트웨이에서 일괄적으로 처리하여, 백엔드 서비스의 보안 로직을 단순화합니다.
* 동적 라우팅: 요청 경로에 따라 적절한 백엔드 서비스로 요청을 전달합니다.
* 논블로킹 처리: `Spring Cloud Gateway` 및 `Spring WebFlux`를 사용하여 수많은 동시 요청을 효율적으로 처리합니다.
* 비동기 메시징: Kafka와 연동하여 필요에 따라 메시지를 발행하고 비동기 워크플로우를 구축합니다.



### 아키텍처 구성

본 게이트웨이는 전체 마이크로서비스 아키텍처의 중심 축 역할을 수행합니다.

1.  클라이언트 (Client)
    * 역할: 웹 브라우저, 모바일 앱 등 사용자가 직접 사용하는 인터페이스. 모든 요청을 API 게이트웨이로 보냅니다.
2.  API 게이트웨이 (API Gateway)
    * 역할: 모든 외부 요청의 유일한 진입점. 인가(JWT 검증), 라우팅, 로깅을 담당합니다. 백엔드 서비스로부터 받은 응답을 클라이언트에게 다시 전달합니다.
3.  백엔드 서비스
    * 역할: 게이트웨이를 통해 요청을 받는 내부 서비스들. 엣지 서버와 코어 서비스가 이 계층에 포함됩니다. 비즈니스 로직에만 집중하고, 보안은 게이트웨이를 신뢰합니다.



### 전체적인 흐름

1.  클라이언트가 게이트웨이에 요청을 보냅니다.
2.  게이트웨이가 요청의 유효성을 검증합니다.
3.  게이트웨이가 요청을 적절한 백엔드 서비스(예: 엣지 서버)로 전달합니다.
4.  백엔드 서비스는 요청을 처리한 후 응답을 생성합니다.
5.  응답은 게이트웨이를 거쳐 다시 클라이언트에게 전달됩니다.
